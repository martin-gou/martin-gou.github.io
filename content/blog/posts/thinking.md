# My tips for learning and thinking

This is a short list of principles that helped me the most when learning difficult topics.

## 1. Learn by building

Reading is useful, but building forces clarity.

When I try to implement an idea, hidden gaps appear immediately:

- I thought I understood it, but I cannot explain it
- I can explain it, but I cannot use it
- I can use it, but only in a narrow case

That feedback loop is extremely valuable.

## 2. Write to think

Writing is not just documentation. It is a thinking tool.

When I write a note, blog post, or even a rough outline, I can see weak assumptions much faster.

If I cannot explain something simply, I usually do not understand it yet.

## 3. Separate exploration from execution

I try to keep two modes:

- **Exploration mode**: collect ideas, test directions, accept messiness
- **Execution mode**: narrow scope, finish the thing, reduce context switching

Mixing them all the time makes progress slower.

## 4. Make your learning environment frictionless

Good learning habits are easier when the setup is simple:

- clear folder structure
- reusable templates
- short commands to run projects
- quick notes while reading or debugging

Small frictions add up.

## 5. Revisit ideas after time passes

A concept feels different after one week of practice.

I like to revisit:

- notes I wrote too early
- code I wrote when I was confused
- old explanations that now feel incomplete

That is where real understanding grows.

## 6. Protect curiosity

Sometimes learning becomes only "finish tasks quickly". I try to keep some time for side questions.

Side questions often become the most interesting projects.

## Closing thought

Progress is usually less about one big breakthrough and more about consistent feedback loops:

- build
- reflect
- rewrite
- improve

That loop works for both engineering and life.
